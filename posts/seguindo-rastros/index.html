O que o JavaScript pode revelar


Durante meus estudos de segurança web, uma coisa que sempre chamou minha atenção é entender como uma aplicação realmente funciona por trás dos panos.

Muitas vezes, a interface é apenas a parte mais visível de uma aplicação. Por trás de cada botão, formulário e página existem chamadas, endpoints e regras responsáveis por fazer tudo funcionar.

E explorando a aplicação encontrei uma funcionalidade que não estava exposta diretamente para os usuários, mas que revelou uma falha de autorização em uma aplicação interna.


A aplicação utilizava Angular como framework no frontend, oque me fez querer olhar os arquivos JavaScript carregados pelo navegador.

A ideia não era simplesmente procurar uma vulnerabilidade, mas entender melhor a estrutura da aplicação:
- quais endpoints eram utilizados
- como as funcionalidades eram implementadas
- quais informações estavam disponíveis no lado do cliente

Durante essa análise, encontrei uma função chamada createUser() responsável pela criação de usuários.

Ao acompanhar seu funcionamento, identifiquei uma chamada para o endpoint: /new/edit

Uma característica interessante em aplicações web é que uma funcionalidade não deixa de existir apenas porque um botão não está visível para determinado usuário.

Ao testar esse endpoint, percebi que ele permitia acessar uma funcionalidade que normalmente estaria restrita a usuários administrativos.

A falha ficou mais clara quando observei que a funcionalidade permitia criar novos usuários e controlar informações que deveriam ser restritas, como o nível de acesso da conta criada.

Isso significava que um usuário sem privilégios administrativos poderia executar uma ação que deveria estar protegida por uma validação de autorização.

O problema não estava na existência de uma rota para criação de usuários. Funcionalidades administrativas precisam existir dentro de uma aplicação.

A falha estava na forma como essa funcionalidade era protegida. A aplicação não realizava uma validação adequada de autorização no backend antes de permitir a execução da ação.


Essa foi uma das situações que reforçou algo que venho estudando. Nem sempre uma vulnerabilidade está em uma técnica complexa.

Muitas vezes, ela aparece quando questionamos o funcionamento da aplicação:

"Essa funcionalidade realmente deveria estar disponível para esse usuário?"

A análise de JavaScript, o entendimento da comunicação entre frontend e backend e a busca por falhas de lógica são partes que considero muito interessantes.

No fim, muitas falhas começam com uma simples curiosidade.
