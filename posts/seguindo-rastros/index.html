O que o JavaScript revela


Durante meus estudos de segurança web, uma coisa que sempre chamou minha atenção é entender como uma aplicação realmente funciona por trás dos panos.

Muitas vezes, a interface é apenas a parte mais visível de uma aplicação. Por trás de cada botão, formulário e página existem chamadas, endpoints e regras responsáveis por fazer tudo funcionar.

Foi justamente explorando uma aplicação que encontrei uma funcionalidade que não estava exposta diretamente aos usuários, mas que acabou revelando uma falha de autorização em uma aplicação interna.

A aplicação utilizava Angular como framework no frontend, o que me fez abrir os arquivos JavaScript carregados pelo navegador.

A ideia não era simplesmente procurar uma vulnerabilidade, mas entender melhor como aquela aplicação era construída. Quais endpoints eram utilizados? Como as funcionalidades eram implementadas? Quais informações estavam disponíveis no lado do cliente?

Durante essa análise, encontrei uma função chamada createUser(), responsável pela criação de usuários.

Ao acompanhar seu funcionamento, identifiquei uma chamada para o endpoint /new/edit.

Uma característica interessante em aplicações web é que uma funcionalidade não deixa de existir apenas porque um botão não está visível para determinado usuário.

Ao testar esse endpoint, percebi que ele permitia acessar uma funcionalidade normalmente restrita a usuários administrativos.

A situação ficou ainda mais clara quando observei que essa funcionalidade permitia criar novos usuários e definir informações sensíveis, como o nível de acesso da conta criada.

Na prática, isso significava que um usuário sem privilégios administrativos conseguia executar uma ação que deveria estar protegida por uma validação de autorização.

O problema não estava na existência da funcionalidade. Afinal, aplicações precisam de áreas administrativas.

A falha estava na ausência de uma validação adequada de autorização no backend antes da execução da ação.

Essa experiência reforçou algo que venho aprendendo durante meus estudos: nem sempre uma vulnerabilidade surge a partir de uma técnica complexa.

Muitas vezes, ela aparece quando simplesmente questionamos o funcionamento da aplicação:

"Essa funcionalidade realmente deveria estar disponível para esse usuário?"

É justamente isso que mais me interessa. Ler o JavaScript, entender a comunicação entre frontend e backend e questionar o comportamento da aplicação.

No fim, muitas falhas começam com uma simples curiosidade.
